# 前端双主题设计

## 设计目标

- 默认提供克制的蓝白主题，降低大面积绿色、渐变、厚阴影和高圆角带来的视觉负担。
- 保留原有浅绿色主题；未登录时不显示主题入口，登录后可在账户菜单中切换。
- 本轮优先完成 PC 端全局视觉统一；手机端只保证已有响应式能力不被破坏，不做平板专项适配。

## 技术取舍

- 使用 `html[data-ui-theme]`、CSS variables 与 `localStorage`，不引入额外主题依赖。
- 默认主题为 `blue`；仅当本地明确保存为 `green` 时恢复浅绿色主题。
- 浅绿色主题继续使用原样式文件，避免重写后出现视觉偏差；蓝白主题放在独立的 `theme.css` 中，通过更高层级选择器覆盖视觉属性。
- 颜色 token：核心蓝 `rgb(0, 100, 221)` / `#0064DD`，深蓝文字 `#004AA8`，交互蓝 `#0058C7`，淡蓝选中面 `#EAF3FF`，雾蓝背景 `#F4F8FE`，蓝灰边线 `#D7E4F6`，正文 `#17223B`，弱化文字 `#7B879C`。
- 字体不依赖外部网络资源：标题优先使用 `Segoe UI Variable Display`，正文使用 `Inter / Segoe UI Variable Text / PingFang SC` 系统回退链。

## 调用链与文件

1. `web-ui/src/main.js` 在 Vue 挂载前读取 `find-job-ui-theme`，提前设置 `data-ui-theme`，避免首屏主题闪烁。
2. `web-ui/src/App.vue` 持有主题状态并负责写入 DOM 与 `localStorage`。
3. `web-ui/src/components/ThemeSwitcher.vue` 为登录后的账户菜单提供可访问主题选择控件。
4. `web-ui/src/theme.css` 定义主题 token，并统一侧栏、卡片、按钮、表单及工作台、求职助手、简历助手、面经库、技能库、评测中心、监控与管理页的蓝白样式。
5. 通过 Vue `Teleport` 挂载到 `body` 的浮层使用 `html[data-ui-theme] body` 级选择器接入同一套 token，不依赖业务页面容器作为主题父级。
6. 面经采集与文件导入弹窗的成功通知、上传区、归档选项、解析进度、图文识别选项、人工确认说明、统计卡片与有效候选状态统一复用蓝色 token；警告与失败仍保留橙色、红色语义。
7. 技能库 Star 圆环及 Teleport 统计浮层使用蓝色强调色和蓝灰边界；无 GitHub 仓库来源的本地 Skill 不渲染空统计圆环。

## 顶栏账户面包屑

- 登录后的顶栏仅展示 `用户 / 角色` 身份路径与下拉箭头，不再长期陈列主题按钮、角色标签和退出按钮。
- 下拉菜单保持两个一级入口：“个人信息”展开账户、角色和退出操作；“主题切换”展开蓝白、浅绿两个主题选项。
- 菜单支持点击外部或按 `Esc` 关闭；移动端隐藏角色路径并继续保留账户入口。
- 主题选择继续调用 `setUiTheme`，即时更新 `html[data-ui-theme]` 并写入 `localStorage`，刷新后保持选择。

## 视觉规则

- 每个业务路由只承载一个主要任务；完整功能通过子路由切换，不在单页纵向堆叠。
- 页面标题、分区标题和导航统一使用中文，不再用英文眉题装饰中文标题；产品名、技术名词和真实数据除外。
- `#0064DD` 只用于主按钮、当前导航和关键进度；链接、文字、选中背景、边线分别使用深蓝、淡蓝与蓝灰派生色，避免全页面使用同一个色号。
- 失败与警告继续保留红、橙语义；普通“已完成 / 可检索 / 已就绪”在蓝白主题中使用派生蓝，避免重新形成一套大面积绿色视觉。
- 卡片以细边框分层，默认不使用投影；Hover 只改变边框或背景，不做明显上浮。
- 主按钮使用实心蓝色，次级按钮使用白底细边框；圆角控制在 7–12px。
- 侧栏当前项使用淡蓝底与左侧定位线，这是蓝白主题唯一的标志性结构元素。
- 登录页以五段“求职轨道”串联简历分析、真实岗位获取、岗位匹配度分析、智能一键打招呼和实时面试助手；轨道之外不增加无业务含义的装饰模块。

## 验证结果

- `npm run build`：通过。
- PC 登录页视觉检查：默认蓝白主题、未登录主题入口隐藏、五段求职轨道、表单焦点与按钮层级正常。
- 主题持久化检查：切换为浅绿后刷新仍为浅绿，再切回蓝白后即时生效。
- 第二轮覆盖：求职助手通知与空态、面经树形索引与正文、工作台四类卡片预览已接入主题色阶。
- 模型与连接、免费模型目录、添加或编辑模型连接三个 Teleport 弹窗已接入蓝白主题；浅绿主题继续沿用原组件样式。
- 面经采集和文件导入 Teleport 弹窗的初始态、解析态与完成态已补齐蓝白覆盖；页头重复的“导入材料”已删除，空态主入口保留。
- 技能库列表 Star 圆环与 Teleport 统计浮层已补齐蓝白覆盖；`interview-library-theme.test.js`、`skill-star-theme.test.js` 负责静态主题回归。
- `prefers-reduced-motion` 已覆盖，键盘焦点保持可见。

## 后续边界

- 新增页面应优先复用现有 token 和通用按钮/表单视觉，不继续添加独立绿色值、渐变或大阴影。
- 手机端若需专项优化，应在 PC 端交互确认后单独调整；不包含 iPad 或平板专项设计。

## 2026-08-25：个人信息账号展示

- **设计目标**：个人信息展开区直接展示当前登录用户的邮箱账号，方便用户确认正在使用的登录身份。

- **调用链**：`/api/auth/me` 及登录响应中的 `user.email` 写入 `App.vue` 的 `authUser`，再由 `accountIdentifier` 统一生成展示值。
- **依赖**：复用现有平台会话用户结构和账户菜单，不增加接口、状态库或第三方依赖。
- **验证结果**：`account-profile.test.js` 覆盖字段文案、未绑定占位和长账号换行；前端完整测试与构建通过。
- **后续边界**：本次仅展示账号，不包含邮箱绑定、换绑、验证状态或账号管理功能。

## 2026-08-27：未登录求职助手首页

- **设计目标**：把登录页左侧从通用“职业智能工作台”叙事改为“求职助手”单一主题，在未登录状态隐藏主题切换功能，并用连续、紧凑的 Agent 执行轨说明平台怎样把用户从简历推进到面试。
- **技术取舍**：不改变认证接口与表单状态；`LoginPage.vue` 使用语义化有序列表呈现五个等分站点，删除波形路径、绝对定位按钮、动态详情栏与“全流程协同”尾部文案。执行轨只保留一条直线、一段蓝色进度和一个移动光点，并通过 `prefers-reduced-motion` 提供静态状态。
- **响应式边界**：宽度 `≥ 1024px` 保持左右同屏；`1024–1279px` 收紧标题、轨道标签和表单留白；高度 `≤ 720px` 单独压缩纵向间距；宽度 `≤ 1023.98px` 切换为认证单任务布局。小数断点用于覆盖浏览器缩放产生的亚像素取整，避免临界宽度残留双栏。
- **调用链**：未登录时 `App.vue` 渲染 `LoginPage.vue`；五步执行轨仅承担产品能力说明，不维护交互状态、不触发业务请求；认证表单继续调用现有登录、验证码、注册与重置流程，登录成功后主题设置仍由账户菜单调用 `setUiTheme`。
- **依赖**：复用 Vue、现有双主题 token、内联 SVG 与原生 CSS 动画，不新增图标库、动画库或网络资源。

- **后续边界**：本次不调整认证协议、登录后侧栏、业务路由或手机端专项视觉；浅绿色主题继续使用原有持久化值，未登录时只隐藏切换入口。

## 2026-08-27：历史归档原文入口与蓝白主题

- **设计目标**：历史记录不再只通向图片、音频和视频；用户进入某个 `content_id` 后，可以在同一次归档中继续打开当时保存的完整文章原文，并在历史列表直接识别生成时间。
- **技术取舍**：历史卡片继续进入 `/review/assets?content_id=<id>`，保持“查看一次完整生成归档”的单页任务；媒体卡片下方左侧新增独立“文章原文”入口，再进入 `/review/article?content_id=<id>` 阅读全文。历史文章模式隐藏审核、驳回和重生成操作，不新增历史编辑能力。
- **调用链**：历史列表 `/api/execution-history` 提供 `created_at` → `formatArchiveTimestamp` 生成卡片左下角时间戳；点击卡片后 `refreshDashboard` 调用 `/api/execution-history/{content_id}` → 同一负载同时驱动媒体资源与原文入口 → 点击原文入口继续使用该 `content_id` 渲染 `article_layout.article_html`，缺少排版稿时回退 `content.article_markdown`。
- **主题取舍**：原文入口直接复用 `--ui-*` token；蓝白主题对历史标题、摘要、时间、普通状态、入口卡片和文章阅读区增加显式覆盖，普通归档状态不再泄漏旧版绿色。
- **依赖**：复用现有 Vue 路由状态、历史详情接口、文章排版结果和媒体资源接口，不增加数据库字段、迁移、第三方包或新后端接口。
- **验证结果**：`execution-history-archive.test.js` 4 项通过；前端完整 195 项测试与 Vite 生产构建通过。PC 端本地真实页面验证历史列表、媒体页原文入口、`content_id=19` 全文路由和历史只读保护均正常。
- **后续边界**：本次完成 PC 端布局与现有窄屏自然回退，不进行手机端专项改版；历史正文仍以已有 `generated_contents` 和 `article_layouts` 数据为准，不补造缺失的旧文章。

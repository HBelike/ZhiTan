# 登录态刷新认证页重定向修复

## 设计目标

已登录用户刷新 `/login`、`/register` 或 `/forgot-password` 时，直接定向到求职首页 `/career`，不再进入只有应用外壳、没有页面内容的空白状态。未登录用户访问认证页面的行为保持不变。

## 技术取舍

- 在 `navigation-access.js` 中集中定义登录态路由解析规则，避免应用启动和登录成功两条链路分别维护重定向判断。
- 使用 `history.replaceState` 替换认证页历史记录，防止用户后退时再次回到不适用于登录态的认证页面。
- 不引入 Vue Router，不调整现有模块权限模型，保持本次修复边界最小。

## 调用链

1. `App.vue` 启动后通过 `/api/auth/me` 恢复当前用户。
2. 恢复成功后调用 `resolveAuthenticatedRoute(currentRoute)`。
3. 认证路由被解析为 `/career`，同步更新浏览器地址与 `currentRoute`。
4. 加载导航模块配置并继续执行现有权限校验；如果求职助手模块对普通用户不可用，仍由现有模块权限逻辑选择首个可访问页面。
5. 用户刚完成登录时复用同一个解析函数。

## 依赖

- 仅依赖现有 Vue 应用状态、History API 和 `/api/auth/me` 登录态接口。
- 无新增运行时依赖。

## 验证结果

- `node --test src/navigation-access.test.js`：通过，覆盖三个认证路由和普通业务路由。
- `npm test`：204 项测试全部通过。
- `npm run build`：生产构建通过；仅保留项目原有的大 chunk 提示，不影响本次路由修复。

## 后续边界

- 本次不修改未登录用户的登录、注册、找回密码流程。
- 本次不修改管理员配置的模块访问权限，也不增加新的路由框架。

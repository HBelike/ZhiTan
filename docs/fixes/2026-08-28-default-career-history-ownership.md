# 旧版求职历史归属管理员修复

## 设计目标

修复本地关闭强制登录时，浏览器已登录但 Career API 仍使用固定默认 Actor，导致历史会话无法按真实账号展示的问题。按已确认的数据规则，旧默认 Actor 下的全部求职会话统一归属平台唯一管理员；新会话继续归属实际登录账号。

## 技术取舍

- 使用 Alembic 数据迁移固化规则，使未来经单独投产授权执行数据库升级时，生产环境遵循相同归属规则。
- 本次只在本机 `127.0.0.1:54329` 对应的 Docker PostgreSQL 执行，没有连接、部署或重建生产环境。
- 迁移只在发现旧默认 Actor 会话时运行，并强制校验唯一有效管理员邮箱为 `admin@example.com`、管理员与默认 Actor 属于同一组织；校验失败则事务回滚。
- 管理员已有同名职业空间时复用现有空间，避免 `(organization_id, actor_id, normalized_name)` 和默认空间唯一约束冲突。
- 不删除旧会话、消息或上下文；数据归属迁移不可逆，`downgrade` 不猜测原创建账号。
- 面经、直播面试和简历优化不属于本次求职历史修复范围，不调整其归属。

## 调用链与依赖

浏览器 `platform_session` Cookie → `enforce_platform_access` 解析真实平台用户 → `CareerRequestActor.actor_id` → 创建会话写入真实 `actor_id` → 历史列表按当前 `actor_id` 查询。

历史修复由 `20260828_29` 数据迁移完成，依赖 `20260828_28` 已建立的单一 Alembic 主线，以及 `20260825_20` 固定的唯一管理员角色和邮箱约束。

## 本地迁移结果

- 43 个会话归属管理员：41 个 active、2 个 archived。
- 91 个 Agent Turn、4 份候选人档案、16 份目标岗位档案、3 个会话压缩任务和 14 个岗位匹配评估同步归属管理员。
- 160 条消息通过会话外键保持完整，无需单独更新归属字段。
- 旧会话引用管理员现有的默认职业空间，没有删除历史内容。

## 验证与边界

- `python -m alembic heads`：单一 head 为 `20260828_29`。
- `python -m alembic upgrade head`：本地事务执行成功。
- 迁移后默认 Actor 的会话和关联上下文归属数量均为 0；管理员拥有全部 43 个会话。
- 身份透传测试同时断言可选认证模式下仍传递真实管理员 `actor_id` 和 `role`。
- 生产环境尚未执行该迁移；任何生产升级仍需用户当次明确授权“部署到生产”或“投产”。

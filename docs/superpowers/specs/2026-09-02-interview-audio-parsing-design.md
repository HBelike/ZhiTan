# 面经库音频解析设计

## 目标

在面经库页面新增“音频解析”入口。用户先填写公司名称和面试岗位，再选择本地面试录音并点击“解析并落库”。系统使用离线语音识别完成转写与说话人分离，只提取可由转写片段证明的面试官问题，随后复用现有面经 Markdown、切片和 RAG 索引链路完成入库。

首版只完成 PC 端功能和交互验证，不进行手机端或平板端专项适配，不部署生产环境。

## 已确认的产品行为

1. 面经库顶部操作区在“小红书URL读取”左侧新增“音频解析”按钮，对应需求截图中的预留位置。
2. 点击按钮打开独立弹窗，页面单一任务是完成一份面试录音的归档，不与现有文档上传弹窗混合。
3. 公司名称和面试岗位由用户在选择录音前填写，均为必填项；系统不尝试从音频中推断或覆盖这两个字段。
4. 面试日期为可选项。未填写时沿用面经库现有“日期待补充”命名规则。
5. 用户选择一个音频文件后点击“解析并落库”。系统展示上传、音频规范化、语音转写、问题提取、建立索引五个阶段的进度。
6. 只要成功提取至少一个可靠问题，就自动生成 Markdown 并写入面经库；成功后关闭弹窗、刷新公司树并打开新入库的面经。
7. 未提取到问题、转写失败或模型不可用时不创建面经，弹窗保留用户填写的公司、岗位和已选文件信息，允许直接重试。

## 技术方案选择

### 采用方案

采用“复用现有基础设施，新增离线音频适配层”的混合方案：

- 复用当前 DashScope API Key、模型连接基础设施、临时文件目录、面经服务、切片器、向量索引降级策略和页面视觉语言。
- 新增离线 `AudioTranscriptionProvider`，首版仅实现 DashScope `qwen-audio-3.0-asr-flash-filetrans`。
- 新增专用 `AudioInterviewQuestionExtractor`，让文本模型只选择原始转写片段编号，不允许自由生成问题正文。
- 不把完整音频模拟成 PCM 实时流，也不复用实时 WebSocket Provider。实时 Provider 的会话、VAD 和提交协议不适合长文件任务，且无法直接提供离线说话人分离结果。
- 不在首版部署 WhisperX、FunASR 或 pyannote，也不新增 GPU 服务。Provider 协议保留以后增加 OpenAI 或本地实现的空间。

### 模型选择

默认模型必须是 `qwen-audio-3.0-asr-flash-filetrans`，而不是当前实时链路使用的 `qwen-audio-3.0-asr-flash-streaming`，也不是不在官方说话人分离支持列表中的 `qwen3-asr-flash-filetrans`。

请求开启 `diarization_enabled=true`，读取每个句子的 `speaker_id`、`begin_time`、`end_time` 和 `text`。音频在提交前统一规范化为单声道，最大允许时长为 2 小时，符合官方对说话人分离的建议边界。

## 组件与职责

### `TemporaryAudioStore`

- 接收单个上传文件并按扩展名和 MIME 双重校验。
- 首版支持 MP3、WAV、M4A、AAC、OGG、WebM 和 MP4 容器。
- 上传上限为 512MB；超过上限时在读取过程中停止并删除已写入的临时文件。
- 使用项目现有 `imageio-ffmpeg` 将输入规范化为 16kHz、单声道 MP3，并读取真实时长。
- 音频超过 2 小时或没有有效音轨时终止处理。
- 无论成功、失败还是客户端中断，都删除原文件和规范化文件。

### `TemporaryAudioSourceRegistry`

DashScope 长音频异步接口只接受公网可访问 URL。注册器为规范化后的文件生成 256 位随机令牌，并通过只读接口提供短时访问：

`GET /api/career/interview-library/audio-sources/{token}`

- URL 的基础域名来自显式配置 `CAREER_AUDIO_PUBLIC_BASE_URL`，必须是 HTTPS；不从未校验的 Host 请求头推断生产地址。
- 令牌只保存在当前 API 进程内存中，默认 30 分钟失效，不写数据库。
- 接口只允许访问音频临时根目录下已经登记的精确文件，不接受任意路径参数。
- 平台身份中间件只对 `/api/career/interview-library/audio-sources/` 这个精确前缀增加公开豁免；其他面经库接口继续要求现有登录会话，回源接口的唯一访问凭据是不可枚举的随机令牌。
- 转写完成或失败后立即撤销令牌；Nginx 对该路径关闭访问日志，避免令牌进入普通访问日志。
- 当前生产镜像使用单 Uvicorn 进程，因此内存注册器与 DashScope 回源请求落在同一进程。未来若扩展为多 API 实例，再将该边界替换为带过期时间的对象存储签名 URL。

### `DashScopeFileTranscriptionProvider`

- 使用现有 `DASHSCOPE_API_KEY` 和可选 `DASHSCOPE_WORKSPACE_ID`。
- API 根地址由 `DASHSCOPE_FILE_ASR_BASE_URL` 配置，适配现有 Key 所属地域；不得根据前端输入切换上游地址。
- 通过 DashScope 异步任务接口提交短时音频 URL，轮询任务状态，并在成功后立即下载 24 小时有效的结果 JSON。
- 对外只返回稳定领域对象：录音时长、带匿名说话人编号的有序句子和 Provider 名称。
- 上游任务 ID、返回 URL 和上游原始响应不写入面经正文或前端；结果下载地址必须是 HTTPS 且属于受信任的阿里云域名，日志只记录状态、耗时、句子数和错误分类。
- 网络、限流、上游失败和结果结构异常分别转换成可读错误，不把 API Key、临时 URL 或上游完整响应暴露给浏览器。

### `AudioInterviewQuestionExtractor`

1. 清理空句和纯语气词，把相邻且 `speaker_id` 相同的短句合并成稳定话轮，每个话轮分配不可变整数 ID。
2. 从全场均匀抽取有限数量的话轮，请求现有文本模型返回 `interviewer_speaker_id` 和判断置信度。
3. 只把该说话人的话轮分批交给模型，要求返回 `question_turn_ids`，不得返回改写后的问题文本。
4. 服务端校验每个 ID 必须存在且属于已选说话人，再复制对应原文、规范空白并复用现有保守去重键。
5. 模型不可用或结构化结果无效时，使用中文疑问词、请求式问法和问号的确定性规则兜底；兜底仍然只选择原始话轮。
6. 如果两个说话人无法可靠区分，或最终没有任何问题，则返回失败，不以低质量空面经降级入库。

这个约束保证最终问题都能回溯到转写原句，避免文本模型凭空补充面试题。候选人在面试末尾提出的反问不会因为带问号就自动归入面试官问题：说话人先判定，问题再选择。

### `InterviewAudioImportService`

- 编排音频规范化、临时来源注册、DashScope 转写、问题提取和面经入库。
- 使用用户填写的公司、岗位和可选日期生成 Markdown：

```markdown
# 示例公司 · 后端开发面经

- 面试日期：2026-09-02
- 来源：上传录音解析

## 面试问题

1. 请介绍一下你负责的项目。
2. 这个系统为什么选择消息队列？
```

- 新增来源类型 `audio_upload` 和触发类型 `manual_audio`，标签至少包含“录音解析”。
- 调用现有 `InterviewLibraryService.ingest` 完成公司归档、正文哈希、切片、关键词检索和可选向量索引。
- 完整转写、候选人回答、音频字节、临时路径和说话人声纹均不持久化。长期数据只有用户填写的元数据、选中的问题 Markdown、摘要、标签和现有索引字段。

## API 与前端数据流

新增流式接口：

`POST /api/career/interview-library/audio-import-stream`

请求为 `multipart/form-data`：

- `company_name`：必填，最长 120 字符。
- `role_name`：必填，最长 160 字符。
- `interview_date`：可选日期。
- `audio_file`：必填，单文件。

响应为现有文件预解析已经使用的 NDJSON 风格事件：

- `progress`：阶段、百分比和面向用户的说明。
- `result`：现有 `_interview_experience_payload` 结构，前端可直接刷新树并选中新面经。
- `error`：稳定错误消息，不包含临时文件路径、令牌、模型密钥或上游响应。

请求生命周期覆盖完整处理过程。Nginx 为该精确路径单独设置 520MB 请求体上限和 60 分钟读取超时，使 512MB 文件加上 multipart 边界后仍可通过，同时不扩大其他 API 的上传边界。客户端关闭或请求取消时，服务端在 `finally` 中撤销临时来源并删除文件；已经提交给 DashScope 的远端任务不保存结果，也不会继续写入面经库。

## 页面设计

页面沿用当前蓝白面经库风格，不引入新的字体、颜色体系或装饰性英文眉题。顶部新增安静型按钮“音频解析”，使用声波图形作为唯一新增识别符号。

弹窗保持单页单任务：

1. 顶部说明“填写归属后上传一段面试录音，系统只保存识别出的面试官问题”。
2. 第一行展示公司名称、面试岗位和可选面试日期。
3. 归属字段填写完整后启用文件选择区；文件区展示支持格式、文件名和大小。
4. 主按钮始终命名为“解析并落库”，处理中替换为当前阶段文本并禁止重复提交或关闭。
5. 进度区用五个真实阶段编码处理顺序，不展示虚构的细粒度百分比。
6. 成功后沿用现有入库完成行为；失败后在对应区域给出原因和下一步，例如“录音超过 2 小时，请裁剪后重试”或“未识别到面试官问题，请确认录音包含双方对话”。

PC 端完成后只验证现有小屏断点不会造成弹窗溢出；手机端交互优化留待 PC 验收后单独处理。

## 配置与部署边界

新增环境变量：

- `CAREER_AUDIO_PUBLIC_BASE_URL=`：DashScope 回源使用的 HTTPS 站点根地址。
- `DASHSCOPE_FILE_ASR_BASE_URL=https://dashscope.aliyuncs.com/api/v1`：与现有 DashScope Key 地域匹配的离线任务 API 根地址。
- `DASHSCOPE_FILE_ASR_MODEL=qwen-audio-3.0-asr-flash-filetrans`：允许固定快照时覆盖，但首版只支持具备说话人分离的模型族。
- `CAREER_AUDIO_MAX_BYTES=536870912`：默认 512MB。
- `CAREER_AUDIO_MAX_DURATION_SECONDS=7200`：默认 2 小时。
- `CAREER_AUDIO_SOURCE_TTL_SECONDS=1800`：默认 30 分钟。

本次只更新示例配置、Compose 变量透传和 Nginx 本地配置，不填写真实密钥，不连接生产服务器，不部署或重建生产容器。

## 错误处理

- DashScope Key、公网基础地址或离线任务 API 根地址缺失：返回 503，并提示管理员补充音频解析配置。
- 类型、体积或时长不符合要求：返回可操作的 422 错误，且不调用 ASR。
- ffmpeg 处理失败：提示录音无法读取或格式损坏，并清理所有临时文件。
- DashScope 提交、轮询、限流或结果下载失败：显示“语音转写暂时未完成，请重试”，服务端记录错误分类。
- 文本模型不可用：执行确定性问题规则；规则仍无结果时不入库。
- 数据库或索引失败：沿用现有面经服务的事务和向量索引降级策略；正文事务失败时不报告成功。
- 同公司、岗位和日期已有面经：沿用现有唯一键和创建者/管理员写权限，不绕过现有防覆盖逻辑。

## 验证策略

### 后端单元测试

- 音频扩展名与 MIME 双重校验、流式大小上限、两小时边界和清理逻辑。
- ffmpeg 命令参数确保 16kHz、单声道输出，并正确读取时长。
- 临时来源令牌不可猜测、过期失效、撤销失效、目录越界拒绝。
- DashScope 提交参数包含正确模型和 `diarization_enabled=true`，轮询成功、失败、限流、超时与畸形结果均映射为稳定结果或错误。
- 话轮合并、面试官选择、仅接受合法话轮 ID、跨批次去重、候选人反问排除和确定性降级。
- 编排服务在成功、异常和取消路径都撤销 URL 并清理音频；只有存在问题时调用 `InterviewLibraryService.ingest`。
- 新来源类型和触发类型的数据库约束迁移可升级、可降级。

### API 测试

- 缺少公司、岗位、文件或功能配置时返回明确状态码。
- 成功流依次返回五个进度阶段和一个结果事件，结果使用现有面经 payload。
- 未识别到问题、Provider 失败和客户端取消时不写入面经。
- 临时来源接口只读取当前登记文件，过期或未知令牌返回 404。

### 前端测试

- 顶部按钮位于指定位置，标题和操作文案均为中文。
- 公司和岗位填写前不能选择文件；支持格式和单文件限制正确。
- `FormData` 字段、NDJSON 进度、错误提示、重复提交锁定与成功后树刷新正确。
- 现有文档上传、小红书 URL 和公开信息收集入口不受影响。

### 本地验收

- 后端相关 pytest 回归。
- `npm --prefix web-ui test` 中面经库相关测试。
- `npm --prefix web-ui run build`。
- 使用 Mock Provider 完成一段双人中文录音的端到端验证；不在自动化测试中调用真实付费 ASR。
- 启动本地页面进行 PC 截图检查，确认顶部操作区、弹窗、进度态和错误态没有布局回归。

## 非目标与后续边界

- 首版不保存完整逐字稿、候选人回答、音频文件或声纹。
- 首版不提供音频播放器、逐句校对、问题编辑预览、批量录音上传、断点续传和后台任务恢复。
- 首版不自动推断公司或岗位，不生成面试答案、复盘建议或候选人表现评分。
- 首版不实现 OpenAI、WhisperX 或 FunASR Provider；只保留稳定接口。
- 若真实录音评测显示 DashScope 在中文技术术语或说话人分离上不达标，再使用相同输入集对 OpenAI Diarize 或本地 FunASR 做 A/B 评测后决定替换，不凭单条样例切换 Provider。

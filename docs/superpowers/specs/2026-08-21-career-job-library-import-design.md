# 求职助手职位库导入设计

## 目标

在求职助手当前会话右上角增加“简历资料”和“职位检索”入口。职位检索以弹窗形式完整复用现有职位库；用户选中岗位并在右下角确认后，系统把职位详情转换为现有目标岗位版本，继续复用原有 JD 要求抽取、会话绑定、右侧职位信息画布和四项指标计算。

现有“补充求职资料 → 可选岗位”中的公司、岗位、职位信息文本框和文件导入保持原样。职位库检索只是新增的并行 JD 来源，不增加第二套岗位模型、指标算法或右侧展示组件。

## 用户与单一任务

- 用户：正在求职助手中分析目标岗位的中文求职者。
- 页面单一任务：从实时招聘信息中选定一个岗位，并将它设为当前会话的目标岗位。
- 成功结果：弹窗关闭，右侧职位信息立即显示所选岗位；已有简历时同步出现原有四项指标，没有简历时只展示岗位信息。

## 交互流程

```text
求职助手当前会话
  → 点击右上角“职位检索”
  → 打开职位检索弹窗
  → 使用与职位库相同的搜索、列表、详情交互
  → 选中一条已成功加载完整详情的岗位
  → 点击右下角“确认岗位”
  → 转换为现有 target role payload
  → 创建 target_role_profile
  → 用当前 candidate_profile（若有）和新 target_role_profile 更新会话绑定
  → 使用接口返回的 context 刷新右侧 CareerContextRail
```

新建对话和历史对话均走同一流程。替换历史对话的目标岗位时只影响后续回答，不修改或重算旧消息。

## 页面与弹窗

### 求职助手顶部入口

```text
┌ 当前会话标题 ──────────────────────────────────────────────┐
│ 简历 v1 → 公司 · 岗位 v1               [简历资料] [职位检索] │
└────────────────────────────────────────────────────────────┘
```

- “简历资料”打开现有 `CareerContextSetupDialog` 的简历步骤；它只改变入口位置，不改变简历解析和保存逻辑。
- “职位检索”打开新的职位弹窗。
- 未选择会话时两个入口不渲染；点击“开启新对话”创建会话后立即可用。
- 已有简历或岗位时，按钮增加一个状态圆点和“已添加”辅助文本，但操作名称保持不变。
- 底部现有“求职资料：已添加 N/2”继续作为资料状态和完整管理入口。

### 职位检索弹窗

```text
求职助手 / 职位检索                                      [×]
┌ 与现有职位库相同的搜索栏、连接状态、岗位列表和岗位详情 ┐
│                                                        │
│                                                        │
└────────────────────────────────────────────────────────┘
当前选择：公司 · 岗位              [取消] [确认岗位]
```

- 弹窗宽度 `min(1640px, calc(100vw - 48px))`，高度 `calc(100dvh - 48px)`，PC 端保留职位库左右分栏的信息密度。
- 弹窗主体直接渲染 `JobSearchWorkspace`，不复制职位库模板，不放置手动 JD 入口，也不增加二次编辑页。
- 面包屑只表达位置：“求职助手 / 职位检索”；不承担来源切换功能。
- 底部固定确认轨道显示当前选中公司的简称、岗位名称和详情更新时间。
- “确认岗位”仅在选中岗位、详情加载完成、`description` 非空且当前没有保存请求时可用。
- 按 `Esc`、点击关闭按钮或点击遮罩可取消；保存中禁止关闭，避免用户误认为保存已取消。

## 视觉设计

### 颜色令牌

- `岗位蓝 #0869D8`：主按钮、选中态和弹窗导航。
- `深海蓝 #14213D`：标题和关键岗位信息。
- `资料蓝白 #EAF3FF`：已添加状态、选中岗位底色。
- `边界蓝灰 #D7E4F6`：弹窗、分栏和确认轨道分隔线。
- `连接青 #04A6A6`：浏览器助手连接状态，沿用职位库。
- `薪资红 #F05B52`：仅用于职位薪资，避免与主操作竞争。

### 字体角色

- 展示标题：沿用 `var(--ui-font-display)`，用于会话标题、岗位标题和弹窗标题。
- 正文：沿用 `var(--ui-font-body)`，用于职位描述、状态说明和按钮。
- 数据与时间：沿用 `var(--ui-font-utility)`，用于更新时间、加载数量和辅助状态。

### 布局签名

唯一的强调设计是“选岗确认轨道”：它横跨弹窗底部，把当前选择和确认动作绑定在同一视线上。职位库主体保持原貌，避免用额外渐变、装饰编号或多层卡片削弱信息阅读。

自检后删除了原方案中的来源切换 Tab 和二次编辑页。它们会让弹窗看起来像通用导入向导，也违背“内容与职位库一致、确认后直接进入原链路”的要求。

## 组件边界

### `JobSearchWorkspace.vue`

新增可选属性：

- `selectionMode: Boolean = false`：开启时向父组件暴露选岗状态。

新增事件：

- `selection-change(job | null)`：搜索重置、岗位切换、详情刷新完成或失败时触发。

事件只返回归一化后的职位库对象，不包含组件内部加载状态。确认按钮可用性由弹窗根据 `job.description` 和自己的保存状态判断。

### `CareerJobSearchDialog.vue`

职责：

- 渲染遮罩、面包屑、关闭按钮和确认轨道；
- 以 `selectionMode` 渲染 `JobSearchWorkspace`；
- 保存当前已加载详情的岗位；
- 发出 `confirm(job)` 和 `cancel`；
- 显示保存失败但不修改当前会话上下文。

### `job-library-target-role.js`

提供纯函数：

```javascript
toTargetRolePayload(job) -> {
  company_name,
  role_name,
  source_kind,
  source_label,
  job_text
}
```

该文件只负责确定性字段转换，不调用 API、不读取 Vue 状态，便于离线单元测试。

### `CareerAssistantPage.vue`

职责：

- 在会话标题右侧渲染两个资料入口；
- 管理职位弹窗开关和保存状态；
- 收到确认岗位后创建 target role，再更新当前会话 context；
- 用接口返回值替换 `conversationContext`，让现有右栏自动刷新。

现有 `CareerContextSetupDialog`、`CareerContextRail`、`CareerJobCanvas` 和指标函数不改变职责。

## 字段映射

| 职位库字段 | 目标岗位字段 | 规则 |
|---|---|---|
| `company` / `companyShort` | `company_name` | 优先完整公司名，回退简称 |
| `title` | `role_name` | 去除首尾空白，保持招聘网站原名称 |
| `sourceUrl` | `source_label` | 优先原岗位链接，缺失时使用“BOSS 直聘职位库” |
| 固定值 | `source_kind` | `job_library` |
| 详情与元数据 | `job_text` | 按下述稳定章节顺序生成 |

`job_text` 结构：

```markdown
# 岗位名称

公司：公司全称
薪资：15-30K·14薪
地点：上海 · 杨浦区
经验：经验不限
学历：本科

## 职位描述
招聘网站返回的完整 description

## 技能关键词
关键词 1、关键词 2

## 工作地点
完整地址

## 职位福利
福利 1、福利 2
```

空字段对应的整行或章节不生成。`description` 为空时禁止确认，不能用列表摘要伪造完整 JD。

## 复用的现有后端链路

1. `POST /api/career/target-role-profiles` 保存目标岗位；后端继续调用 `extract_job_requirements(job_text)` 生成 requirements。
2. `POST /api/career/conversations/{id}/context` 用当前简历 ID（若有）和新岗位 ID 创建新 binding version。
3. 返回 `_conversation_context_payload`；有简历和岗位时继续调用 `build_match_assessment` 计算：
   - 技能证据覆盖率；
   - 经验要求达成率；
   - 项目场景适配率；
   - 关键要求缺口率。
4. `CareerContextRail` 和 `CareerJobCanvas` 使用返回数据直接重绘。

不新增数据库迁移、不修改指标公式、不让浏览器直接提交 requirements 或 assessment。

## 状态与异常

- 浏览器助手未连接、BOSS 未登录、验证码或风控：完整复用职位库现有提示，确认按钮保持禁用。
- 搜索结果为空：保留搜索输入并给出缩短关键词的现有建议。
- 岗位详情加载失败或没有正文：保留列表和选中卡片，允许重新获取详情，禁止确认。
- 创建目标岗位失败：弹窗保持打开、当前职位信息不变。
- 目标岗位创建成功但会话绑定失败：缓存已创建的 target role ID；重试时只重试绑定，不重复创建岗位版本。
- 保存成功：关闭弹窗，显示“目标岗位已更新，后续回答将使用新岗位”，右栏使用接口响应刷新。
- 用户切换会话时：关闭弹窗并清空未确认选择，防止岗位写入错误会话。

## 可访问性与响应式

- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和明确标题。
- 打开后焦点进入职位搜索框；关闭后焦点返回“职位检索”按钮。
- `Esc` 关闭仅在未保存时生效；所有操作支持键盘聚焦，焦点环沿用全局主题。
- 低于 `900px` 时职位库弹窗退化为现有职位库的窄屏布局；本轮优先完成并确认 PC，手机端只保证可用，不进行平板专项设计。
- 尊重 `prefers-reduced-motion`，弹窗只保留淡入，不使用位移动画。

## 测试与验收

### 单元测试

- `job-library-target-role.test.js`：完整字段、缺省字段、章节顺序、禁止空 description、输入对象不被修改。
- `JobSearchWorkspace`：搜索重置发出 `null`；详情成功发出完整 job；详情失败发出 `null`。

### 后端回归

- `source_kind=job_library` 可创建 target role。
- 映射后的 `job_text` 继续生成 requirements。
- 只有岗位时 assessment 为 `null`；岗位与简历都有时四项指标保持原算法版本。
- 绑定失败不覆盖原 context。

### PC 验收

1. 新对话和历史对话右上角均出现“简历资料”“职位检索”。
2. 手动输入和文件导入 JD 的现有流程没有变化。
3. 职位弹窗主体与职位库的搜索、列表、详情一致。
4. 未加载完整详情时“确认岗位”不可用。
5. 确认后弹窗关闭，右侧显示所选公司、岗位、职位内容。
6. 当前有简历时四项指标出现；没有简历时只显示岗位信息和补充简历提示。
7. 替换岗位后旧消息不变，下一轮对话使用新 binding version。

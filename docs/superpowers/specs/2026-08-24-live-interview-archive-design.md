# 实时面试归档到面经库设计

## 目标

用户结束浏览器面试后，可以选择把本场识别出的面试问题整理成 Markdown，并归并到现有面经库。归档是可选操作，不能阻塞声音采集停止或实时会话结束。

## 已确认交互

1. 点击“结束面试”后立即停止声音采集、关闭实时连接并停止计时。
2. 随后弹出“保存本次面经？”窗口。
3. 公司、职位由用户每次手动填写；面试日期默认取本场第一次会话开始日期，允许修改。
4. 弹窗只展示问题数量与前 5 个问题，不展示或编辑完整 Markdown。
5. “本次不保存”立即关闭，不二次确认，也不提供之后重新归档的入口。
6. 保存内容只有面试问题，不包含模型答案、候选人麦克风转写、原始音频或闲聊。
7. 同公司、职位和日期的面经自动合并；已有问题保留原顺序，新问题追加并去重。
8. 保存成功后可查看面经；失败时保留表单并允许重试或关闭。

## 数据来源与边界

- 实时面试过程已经持续保存 `final` 转写和问题回答状态；结束动作只负责把会话标记为 `completed` 或 `failed`。
- 归档问题从后端 `live_interview_answers.original_question` 读取，包含 `completed`、`cancelled`、`failed` 等状态，避免遗漏已经识别但未成功生成回答的问题。
- 暂停后重新选择声音来源会创建多个 `session_id`；一次归档必须聚合页面本场积累的全部会话。
- 前端只负责提交 `session_ids` 和用户填写的元数据，不能用本地最多 50 条的问答历史生成文档。
- 不使用 LLM 整理问题。Markdown 由确定性逻辑生成，避免额外成本和内容幻觉。
- “本次不保存”只表示不写入面经库，不删除已经存在的实时会话记录。

## 弹窗结构

弹窗宽度以 PC 端约 640px 为基准，沿用面试大师现有蓝色视觉体系。信息层级如下：

1. 标题“保存本次面经？”与关闭按钮。
2. 摘要：“本场识别到 N 个问题，保存后可在面经库检索。”
3. 公司名称、面试职位、面试日期三个字段。
4. 只读问题预览：最多展示前 5 条，并显示总数与剩余数量。
5. 次按钮“本次不保存”和主按钮“保存到面经库”。

公司、职位、日期只在保存时校验；关闭和不保存始终可操作。零问题时显示明确空状态并禁用保存。

## 归档文档

```markdown
# 字节跳动 · AI Agent 开发工程师面经

- 面试日期：2026-08-24
- 开始时间：14:30
- 结束时间：15:42
- 面试时长：72 分钟
- 来源：面试大师实时整理

## 面试问题

1. 请介绍一下你负责的 Agent 项目。
2. Agent 和 Workflow 有什么区别？
3. 如何处理长对话上下文超限？
```

精确开始、结束时间只写入 Markdown；面经库的结构化字段继续使用现有 `interview_date DATE`。

## 后端方案

新增专用接口：

```text
POST /api/career/live-interviews/archive/preview
POST /api/career/live-interviews/archive
```

预览接口只接收 `session_ids`，返回后端完整历史中的问题总数、前 5 个问题和首次会话日期；避免使用前端最多保留 50 条的本地历史。

请求字段：

```json
{
  "session_ids": ["uuid"],
  "company_name": "字节跳动",
  "role_name": "AI Agent 开发工程师",
  "interview_date": "2026-08-24"
}
```

后端执行：

1. 校验所有会话属于当前组织和用户，并拒绝空会话集合。
2. 按会话时间、问题版本和首次记录顺序聚合问题。
3. 使用规范化问题文本去重，保留第一次出现的原文。
4. 读取同公司、同职位、同日期的已有面经，将新问题追加合并。
5. 生成完整 Markdown，以 `authenticated_session` 来源写入现有 `InterviewLibraryService`。
6. 复用现有切片和检索索引流程。
7. 重复提交同一批会话时保持幂等，不重复追加问题。

## 合并规则

- 目标面经节点仍采用现有“职位 · 日期”名称。
- 合并前解析已有 Markdown 的“面试问题”编号列表；无法解析时保留原正文，并在末尾追加标准问题章节。
- 去重键统一空白、大小写和中英文句末标点，不进行语义改写。
- 合并后重新生成元数据时间范围：开始时间取所有已归档会话的最早值，结束时间取最晚值。
- 若节点不存在则创建；存在则更新完整 Markdown，不允许直接以新文档覆盖旧正文。

## 状态与错误

- 保存中：主按钮显示“正在整理并建立索引…”，禁用重复提交。
- 成功：显示“已保存到面经库”，提供“查看面经”和“返回求职助手”。
- 失败：保留输入和预览，显示服务端可执行错误，可重试或关闭。
- 零问题：提示“本场未识别到可归档的问题”，不发起保存请求。
- 结束连接与归档请求并发时，归档接口短暂等待会话完成落库，再读取问题；超时返回可重试错误。

## 验收标准

- 结束按钮立即停止采集并显示归档弹窗。
- 弹窗完全符合已确认字段、预览和按钮行为。
- 多个 `session_id` 能归并为一场面经。
- 只保存问题，失败或取消回答对应的问题也被保留。
- 同日同岗已有面经不会丢失，重复问题不会新增。
- 重复点击或网络重试不会重复追加。
- 保存成功后面经库能够读取并检索新内容。
- 全部验证仅在本地完成，未经明确授权不部署生产。

# BOSS 真实岗位检索 UI 设计

## 目标

在面经库内增加一个独立的 PC 端岗位检索工作台。用户从面经库点击“URL解析职位”后，只需输入岗位名称，即可在同一页面查看岗位列表与岗位详情；浏览器助手、BOSS 标签页和接口调用过程不进入日常操作界面。

UI 评审完成后，正式实现通过本地 Chrome MV3 助手接入真实 BOSS 数据。正式职位库不保留预览岗位或模拟数据兜底。

## 页面边界

- 面经库 `/interviews` 继续负责面经导入、归档和阅读。
- 岗位检索使用子路由 `/interviews/jobs`，遵守“单页单任务”。
- 面经库工具栏新增“URL解析职位”按钮，点击后进入岗位检索工作台。
- 工作台提供“返回面经库”，不在面经详情页纵向堆叠岗位模块。

## 核心交互

1. 页面打开后，搜索框自动聚焦，默认带入“Agent 软件开发”用于预览。
2. 用户只需输入岗位名称并按 Enter 或点击“搜索真实岗位”。
3. 搜索期间展示短暂的连接与检索状态，完成后显示岗位卡片。
4. 点击岗位卡片后更新右侧详情；真实实现阶段，每次点击都必须重新请求岗位详情。
5. “加载更多岗位”将追加下一页卡片，已选岗位保持不变。
6. 正式页面显示浏览器助手连接状态；扩展不可用时只展示安装指引，不展示模拟岗位。

## 视觉方向

### 色彩 Token

- 雪原蓝 `#F3F7FC`：页面背景，承接平台蓝白主题。
- 纸面白 `#FFFFFF`：列表和正文阅读面。
- 墨蓝 `#14213D`：标题与关键信息。
- 实时蓝 `#0869D8`：搜索按钮、轨道、选中态和键盘焦点。
- 信号青 `#04A6A6`：真实连接状态与在线圆点，仅用于状态。
- 薪资朱红 `#F05B52`：薪资，复用招聘网站语义但降低饱和度。

### 字体

- 标题：`Segoe UI Variable Display`、`PingFang SC`、`Microsoft YaHei`。
- 正文：`Inter`、`Segoe UI Variable Text`、`PingFang SC`。
- 状态与计数：`SFMono-Regular`、`Consolas`，只用于实时状态和页码。

### 布局

- 采用稳定的双栏阅读布局：左栏固定约 `360px`，右栏占剩余空间。
- 搜索带跨越双栏，保持“输入即开始”的第一视觉重心。
- 页面不使用统计卡片、营销式大标题或装饰性英文眉题。

### 标志性元素

“实时检索轨道”是一条从搜索框底部延伸到当前岗位卡片，再落到详情标题左侧的蓝色细线。它表达同一份实时结果在搜索、列表和详情之间的关联，而不是纯装饰。

## 状态设计

- 初始：搜索框聚焦，右侧说明输入岗位名称即可检索。
- 搜索中：搜索按钮显示“正在检索…”，结果区保持骨架或旧结果，避免页面跳动。
- 有结果：列表显示结果数量与更新时间，详情显示当前岗位完整信息。
- 空结果：说明“没有找到匹配岗位”，保留原输入并建议减少关键词。
- 助手未连接：明确提示首次安装或登录，不显示模糊错误。
- 详情请求失败：岗位卡片保留，右侧提供“重新获取详情”。

## 数据字段

列表卡片显示：岗位名、薪资、经验、学历、公司、区域、技能摘要、招聘者在线状态。

详情显示：岗位名、薪资、城市、经验、学历、公司、融资与规模、办公地址、福利、技能、职位描述、更新时间。

## 验收标准

- 用户在岗位检索工作台只需填写一个“岗位名称”输入框。
- 1440px 宽 PC 端能同时看见不少于 3 张岗位卡片与详情首屏。
- 选中态、悬停态、键盘焦点清晰可辨。
- 支持 `prefers-reduced-motion`，不会依赖动画传达状态。
- 页面所有标题和操作均使用中文。
- 正式页面只展示扩展实际返回的岗位，不使用预览数据兜底。

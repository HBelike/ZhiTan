# 对话模型切换时上下文限制刷新设计

## 目标

求职助手在创建新对话、恢复历史对话、切换下拉框模型以及编辑当前模型连接后，必须按照当前实际选中的模型重新估算上下文占用，不能继续展示或使用上一模型的上下文限制。

## 已确认行为

- 对话 ID 或解析后的模型档案 ID 变化时，立即清空旧的上下文占用展示并请求当前模型的 `context-usage`。
- 保存当前正在使用的模型连接时，即使档案 ID 没有变化，也要触发一次重新估算，以应用服务端刚更新的上下文容量。
- 请求必须携带当前 `model_profile_id`，后端按指定模型解析上下文策略。
- 保留递增请求号保护；较早发出的慢响应不能覆盖后来模型的结果。
- 不向普通用户暴露准确上下文 Token 容量，只更新近似占用比例与状态。

## 边界

- 本次仅修改 PC 端现有求职助手模型选择链路，不新增手机端或平板专项交互。
- 不修改模型上下文容量识别规则；容量仍由模型连接保存和迁移逻辑维护。
- 不部署生产环境。

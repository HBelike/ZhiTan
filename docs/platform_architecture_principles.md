# 个人平台架构原则

## 状态

2026-08-07 起生效。本文是微信公众号工作流、求职助手、技能库、知识库及后续模块共同遵守的架构约束。

## 第一性原则：可上线

本项目的最终形态是可公开部署的个人平台，而不是只能在开发者个人电脑上运行的 Demo。因此每项设计先回答以下问题：

1. 部署到无 GPU 的普通云服务器后是否仍可运行；
2. 单个用户的耗时、内存、磁盘和外部 API 成本是否可被限制；
3. 第三方服务、模型或本地组件故障时是否能清楚降级，而非伪造成功；
4. 是否能通过环境变量、Secret 与容器配置完成迁移，而不依赖开发电脑上的手工状态；
5. 是否保留 Provider 替换能力，避免业务逻辑锁死于某个模型或厂商。

## 执行规则

- 云端托管 API 优先。公共请求不依赖开发电脑显卡、Ollama 常驻模型或本地特有路径。
- 本地 GPU 推理仅可作为开发、离线评测或应急兜底，不得成为生产请求的唯一依赖。
- 模型访问经统一 OpenAI-compatible 网关与能力契约接入；业务层仅声明 TEXT、VISION、OCR 等能力需求。
- 文档解析、队列、数据库、对象存储等资源必须能独立容器化和横向扩展。
- 所有 API Key 仅由服务器 Secret 或数据库受控保存，浏览器和日志绝不接触明文。
- 每个新模块或重大调整都要更新对应决策文档，写明目标、调用链、依赖、部署影响、验证结果与已知边界。

## 当前求职助手的直接结论

- 文字对话：可替换云端 LLM；当前保留 DeepSeek 与免费额度 Provider 路由。
- 图片语义理解：云端主连接为百炼 OpenAI-compatible 的 `qwen3.6-flash`；服务端仅需 HTTPS 出网、Workspace API Host 与 `CAREER_DOCUMENT_VISION_API_KEY`，不需要 GPU。视觉模型可通过配置切换，聊天页访客不能修改它。
- 图片文字、表格、扫描件：先由可独立部署的文档解析服务处理；云端 Qwen OCR 是后续可配置复核，而非普通对话模型。
- 原始附件仍只在当前 Turn 临时存在；公网部署前应将临时目录迁移至受限对象存储或短生命周期卷。

## 评审清单

任何实施前至少确认：

- 服务依赖和许可证；
- 无 GPU 服务器上的运行路径；
- 并发、超时、速率限制和成本上限；
- 敏感数据、日志和临时文件边界；
- 失败提示、重试策略和监控指标；
- 本地开发与生产部署配置是否可分离。

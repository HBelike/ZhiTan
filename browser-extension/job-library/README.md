# Find Job 职位库助手

该 Chrome MV3 扩展是业务页面与用户已登录浏览器页面之间的本地通道。它支持 BOSS 直聘职位读取与逐条打招呼、小红书公开面经收集，以及用户主动点击后的当前线上笔试题面识别。

## 首次安装（生产用户）

1. 在职位库或一键打招呼的安装拦截弹窗中下载版本化 ZIP，并解压到一个不会删除的固定目录。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”，选择刚才解压出的目录。
4. 在同一浏览器中登录需要使用的站点：职位功能登录 `https://www.zhipin.com/`，小红书信息收集登录 `https://www.xiaohongshu.com/`。
5. 回到平台刷新页面；右上角显示“助手已连接”后再继续搜索或打招呼。

生产页面同时提供独立图文教程 `/boss-extension-guide.html`。开发人员也可以直接加载本仓库的 `browser-extension/job-library` 目录。

扩展更新后，在扩展管理页点击本扩展的“重新加载”即可。

## 权限与边界

- `tabs`：复用或创建一个非激活的 BOSS 或小红书页面。
- `scripting`：在 BOSS 页面执行只读请求或用户确认后的发送操作；在小红书页面读取当前可见卡片、正文和配图地址。
- 源码中的站点权限仅覆盖本地开发地址、`www.zhipin.com` 和 `www.xiaohongshu.com`；生产站点在打包时显式加入。
- 扩展不读取或导出 Cookie、密码、手机号、聊天记录和简历。
- 扩展不接收整批任务；每次只预检或发送一个岗位，批量顺序由页面严格串行调度。
- 只在用户点击搜索、加载更多或岗位卡片时请求数据；请求串行执行并保留最小间隔。
- 用户切换城市后，扩展只在本次主动搜索时将专用 BOSS 搜索页同步到所选城市；不会改动正在浏览的岗位详情页，也不会后台轮询城市状态。
- 列表返回后会逐条核对岗位城市。与所选城市不一致或没有城市信息的岗位不会展示；整批结果都不一致时立即停止并提示重新检查。
- 扩展不做后台轮询，也不主动探测账号状态。只有本次用户操作返回可恢复的页面会话异常时，才正常刷新 BOSS 页面一次并重试原请求一次。
- 每次用户操作最多自动刷新一次；真实限流、登录失效、安全验证以及刷新后仍异常时均立即停止，不循环刷新、不绕过验证。
- 小红书关键词任务只在一个后台标签页中串行执行；登录、验证或访问频率限制出现时暂停任务并把该标签页切到前台。
- 小红书搜索卡片中的临时签名地址只在扩展内用于打开详情，不发送给后端或写入扩展存储；配图交给后端临时 OCR 后删除，数据库只保留解析文本。
- 线上笔试只在用户点击扩展图标、重新识别或补充题面时读取当前视口；不自动滚动，不读取隐藏测试，不填写或提交第三方页面。

## 调用协议

网页 Content Script 接受以下动作：

- `ping`：检查扩展是否可用。
- `list_cities`：通过 `/wapi/zpgeek/common/data/city/site.json` 读取当前 BOSS 城市目录，返回可用于真实搜索的九位城市代码。
- `search_jobs`：按岗位名称、页码和选中城市搜索职位；城市代码必须为九位数字。
- `get_job_detail`：使用列表响应中的 `securityId` 获取最新详情。
- `preflight_greeting`：只读检查登录、安全验证、岗位有效性和聊天标识，不建立沟通关系。
- `send_greeting`：单次建立一个岗位的沟通关系，在专用后台聊天页填入一条最终文案并点击发送。
- `retry_greeting_message`：只对明确未提交或明确失败的定制文案执行单次重发，不重复建立沟通关系。
- `search_xiaohongshu_notes`：使用当前登录状态按关键词读取 5–50 张笔记卡片。
- `get_xiaohongshu_note`：串行打开一张已发现卡片，读取正文、作者、标签和配图地址。
- `claim_assessment_launch`：领取一次性题面采集并立即删除五分钟有效的启动记录。
- `refresh_assessment_problem`：重新读取最初绑定题目标签页的当前视口并替换题面。
- `append_assessment_problem`：读取用户滚动后的新视口，由 WebUI 去重合并题面。

真实发送不会自动重试 `friend/add` 或页面“发送”点击。BOSS 已配置默认招呼语时，扩展允许平台先发送默认招呼语，再进入聊天页发送本次定制文案。扩展确认文案已写入且发送按钮可用后执行一次点击，并立即把本岗标记为已触发，不再等待送达、已读或失败回执。验证码、限流、登录失效等单岗异常会返回 WebUI 记录，后续岗位仍继续逐条尝试。

网页与扩展通过当前页面的 `window.postMessage` 和 `chrome.runtime.sendMessage` 通信。Service Worker 会校验调用来源，只接受项目本地地址和正式域名。

## 会话恢复

扩展优先复用当前激活或最近访问、且已经加载完成的 BOSS 标签页。搜索岗位、读取详情或发送前预检返回 `code=37` 时，扩展会立即对该 BOSS 标签页执行一次普通刷新，等待页面稳定后只重试刚才的只读请求一次。该机制按用户操作即时触发，不依赖后台定时器，也没有跨操作冷却；`friend/add` 和发送点击本身仍不会自动重试。

如果一次自动刷新后会话仍未恢复，发送进度页会显示“刷新 BOSS 状态，重试这一条并继续”。该按钮只用于尚未提交消息的安全失败；发送结果未知时不会出现，避免重复消息。

以下状态不会触发自动刷新：

- HTTP 或接口 `429` 访问频率限制；
- 登录页、安全验证页或验证码；
- 普通网络错误、未知接口错误；
- 自动刷新后仍返回异常。

该机制不导出、保存或替换 Cookie/token，也不会定时刷新页面。真实发送所需的临时页面 Token 只在注入的 BOSS 页面执行环境中使用，不会返回 WebUI 或写入扩展存储。

城市同步同样只使用浏览器正常页面导航：若已有 BOSS 搜索页但城市不同，则单次切换该搜索页；若只有岗位详情等其他页面，则新建一个非激活搜索页，避免打断用户浏览。

## 维护

BOSS 职位与沟通链路来自其网页当前使用的内部接口和 DOM，并非公开开放 API，字段、路径和选择器可能变化。接口漂移时优先更新 `boss-data.js`、`boss-greeting.js` 与 `service-worker.js`，不把平台原始响应直接暴露给业务页面。

`0.2.2` 修复了 BOSS 已接收消息但页面未渲染 `status-delivery` / `status-read` 时被误判为 `send_unknown` 的问题。该兼容逻辑不会把历史同文案或仍留在输入框中的文案判为成功，也不会重试已经点击过的消息。

`0.2.3` 修复了默认招呼语已建立沟通、定制文案却在聊天页验证前中断后无法继续的问题。扩展只对“尚未点击发送”或“BOSS 明确返回发送失败”的定制文案开放重发；结果未知时仍禁止重试。安全验证只识别验证路由、可见挑战控件和明确挑战文案，不再匹配页面中的普通安全说明。

`0.2.4` 在 `ping` 中声明 `retry_greeting_message` 与 `greeting_submission_state` 能力。Web UI 在真实发送和重试前都会复检能力；旧版扩展只显示更新入口，不再进入无法判断提交阶段的发送流程。失败项的重试入口提升为批次级操作，不受当前选中岗位影响。

`0.2.5` 修复 Chrome 临时锁定标签栏时的发送失败：聊天标签页的 `tabs.update` 与 `tabs.create` 对 `Tabs cannot be edited right now` 执行有限退避重试。锁定持续存在时，助手返回中文 `browser_tab_busy`，明确记录定制文案尚未提交、保留默认招呼状态，并只允许重发定制文案，避免重复调用建立沟通接口。

`0.2.6` 修复 BOSS 已显示新消息气泡却被误判为 `send_unknown` 的问题。发送前记录本人消息逻辑序列，发送后通过受限的本人消息选择器集合和 MutationObserver 识别新增消息；文本只归一化空白、NBSP 与零宽字符。逻辑消息连续存在 2 秒且输入框已清空时确认提交，DOM 节点重绘不会重置计时，历史同文案、消息消失或输入框未清空仍不能伪造成功。

`0.2.7` 将多岗位发送改为“逐岗触发、立即继续”：每次仍只操作一个岗位和同一个聊天标签页，以降低批量并发带来的账号与页面竞争风险；文案写入并点击发送按钮后立即返回 `submitted`，不再监听 BOSS 的送达或成功回执。单岗在点击前失败只记录本岗失败，WebUI 仍继续尝试后续岗位，只有用户主动停止才终止剩余队列。

`0.2.8` 新增小红书关键词信息收集能力：后台标签页读取搜索卡片并逐篇解析正文与配图，账号级登录、验证和限流会暂停整批任务；单篇解析失败继续处理后续卡片。扩展不保存 Cookie、详情签名参数和图片。

`0.2.9` 将小红书详情读取改为从搜索页点击真实卡片并在完成后恢复搜索上下文，不再直接导航临时签名地址。Web 端 `300031`、App 扫码限制会记录为单篇受限并继续；登录、验证和限流仍暂停整批。扩展更新时会向已经打开的业务页幂等补注入通信脚本，避免版本更新后必须手工刷新才能连接。

`0.3.1` 修复 `leetcode.cn` 根域名被误判为 generic 的问题，并从可见 Monaco/CodeMirror starter code 提取函数签名；安装、更新和浏览器启动都会向已打开业务页幂等重注入通信脚本。

`0.3.2` 修复 Chrome 隔离注入题面函数时模块辅助函数不可见的问题；注入失败会保留真实错误原因到扩展图标提示，但不再通过 `console.error` 制造扩展错误记录。

`0.3.0` 新增线上笔试题面识别：点击扩展图标后，通过一次性 `activeTab` 权限读取 LeetCode、HackerRank 或通用当前视口，采集结果暂存在 `chrome.storage.session` 并打开独立助手窗口。扩展只返回清洗后的文本、代码、语言、公开样例候选与当前视口截图，不提供写入、提交、隐藏或反检测动作。

生产下载包由仓库根目录的 `scripts/package_boss_extension.py` 生成，输出到 `web-ui/public/downloads/find-job-boss-helper-v{version}.zip`。使用 `ZHITAN_APP_ORIGIN` 指定公开站点的 HTTPS Origin，打包器会把它同时注入 manifest 权限和 Service Worker；源码不保存实际部署域名。网页的下载版本、ZIP 文件名和 `manifest.json` 必须一致。安装状态不写数据库：页面每次进入依赖 BOSS 的区域时都通过 `ping` 检查当前浏览器，因为同一用户换电脑、换浏览器或停用扩展后，用户级数据库标记都会失真。

验证命令：

```powershell
$env:ZHITAN_APP_ORIGIN = 'https://jobs.example.com'
.\.venv\Scripts\python.exe scripts\package_boss_extension.py

cd browser-extension/job-library
npm test
node --check service-worker.js
node --check content-script.js
```
